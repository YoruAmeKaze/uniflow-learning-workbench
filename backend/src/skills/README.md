# UniFlow 项目内 Skills

这些是服务器内置的 TypeScript 能力模块，通过现有 Tool 查询数据库。无需安装外部 Skill，也不执行模型返回的代码。

## 请求流程

`/api/chat → Agent.processIncoming → Planner → SkillRegistry → Skill → Tool → 模型建议 → 校验 → 回答`

所有符合输入边界的消息先交给当前 `LLM_MODEL` 做只读 Skill 路由，由模型在白名单中选择 Skill 或返回 `none`。不再用关键词正则直接触发计划，也不把普通聊天强行转成计划。模型路由需要合法名称和至少 0.8 的置信度；路由失败或返回 `none` 时回到普通 Agent。

| Skill | 数据范围 | 规划策略 |
| --- | --- | --- |
| daily_schedule | 指定日期的课程、该日前截止的未完成任务、无截止日期事项 | 在目标日期可用时间内安排 |
| weekly_plan | 本自然周剩余课程、截至周日的任务、逾期及无日期事项 | 在本周剩余日期分散安排 |
| deadline_priority | 未来 7 天内未完成作业和待办 | 只整理临近截止任务的顺序，不查询课程 |

## 数据与执行边界

- Skill 只调用 `course`、`todo(list)`、`assignment(list)`；user_id 来自认证上下文，不由模型决定。
- 明确的提醒/新增请求及上传文档走原 Agent 路径，避免把文档里的“计划”当成用户指令。
- 日期运算固定北京时间，本周结束为下周一 00:00，不是未来七天。未完成的逾期任务会标出“需核实补交”，没有截止时间的待办仍保留。
- 每次最多向模型提供截止顺序前 12 项，回答会告知省略数量。模型只接收规划所需字段，没有密码、用户档案、数据库连接信息。
- 工具查询失败/异常/超时记录 failed；不会显示为“没有任务”。课程查询失败时不分配学习时间。缺少身份时不执行查询。
- 查询每步最多等 8 秒；模型路由等 12 秒，生成等 25 秒；Agent SDK 请求另有 20 秒超时和零自动重试。工具超时只停止等待，不中止底层只读查询。

## 模型真正参与什么

模型先根据当前问题选择 Skill，再获得 Skill 的策略说明、真实任务和预先检查过的可用时段，返回结构化的任务顺序及时间块选择。最终文本由事实和有效方案生成；这避免模型改写原有任务名、课程、截止时间。用户提出的休息、长期习惯等偏好目前不作为持久化或强约束处理。

生成契约：`{ order: [taskId], sessions: [{ taskId, slotId }] }`。服务器检查任务全集、不重复、不使用未知时段、不重复占用时段、不在截止后安排、不给逾期任务虚构补交时间。无效 JSON、无效方案或接口失败会退回基础排序。

时段默认 08:00–22:00，每段 30 分钟，避开课程前后 10 分钟和 12:00–13:00、18:00–19:00 用餐时间。这些是起步投入建议，不是预测完成耗时。规则能检查排课冲突，但用户自由文本偏好的满足程度仍依赖模型；校验成功不代表偏好已全部满足。

## 执行记录和界面

聊天响应新增可选 `plan`：skill、label、routing（model）、generation（model/fallback）、steps（工具名、中文名、状态、条数、耗时）。终端只记录状态，不打印任务正文。界面折叠展示“查看安排依据”，不展示网页来源。

## 使用与验证

重启后端后可输入：

1. 帮我安排今天，复习尽量放在晚上。
2. 给我做一个本周计划。
3. 最近事情好多，帮我理一下。
4. 作业我该先做什么？

后端运行 `npm run test:planner`：覆盖 11 个回归场景（固定测试数据，无外部 API），包括周日跨时区、完成/逾期/无日期任务、冲突、无身份、失败查询、无效模型结果、模糊路由、Agent 入口和百炼参数。`npm run smoke` 另外验证 HTTP 响应和真实 Tool + 内存数据库的装配。

开发时已用虚构任务实测当前百炼模型：明确今日请求能选择晚间时段；模糊请求能选中 deadline_priority；也观察到一次无效建议被回退。此为连通性样例，不是模型准确率评测。

## 扩展与当前限制

新增模块实现 `AgentSkill`，在 `index.ts` 注册，并补充需要的路由和测试即可。共享的查询、时间检查在 `planning.ts`；路由及模型调用编排在 `services/planner.ts`。

当前三个 Skill 聚焦单日/本周/优先级；单日 Skill 支持今天、明天、后天、几天后和明确日期。`deadline_priority` 只查询未来 7 天内的未完成作业和待办，不包含课程安排。未实现跨轮偏好记忆、持久化计划、任务工时估算或日程自动写入。通知知识类请求仍使用原 RAG 链路。
